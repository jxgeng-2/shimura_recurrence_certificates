# Section 5, Table 4: four selected CM-image claims

Run from the package directory:

```text
python certificates/cm_claims.py
```

This small certificate uses only Python's standard library. It reads the four
polynomials transcribed from the supplied draft into `data/cm_claims.json` and
writes `results/cm_claims.json`. It does not invoke the under-200 computation.

The checked rows are:

| Elliptic target | D | h(D) | Operator | Polynomial degree |
|---|---:|---:|---|---:|
| 14a1 | -163 | 1 | w2 | 1 |
| 15a1 | -127 | 5 | w3 | 5 |
| 21a1 | -151 | 7 | w21 | 7 |
| 58b1 | -131 | 5 | w29 | 5 |

For every polynomial the certificate checks positive leading coefficient and
integer content one. It proves irreducibility over Q, either by degree one or
by finding a degree-preserving irreducible reduction modulo a small prime.
For the latter it checks the complete finite-field criterion:

\[
x^{p^n}-x\equiv0\pmod f,\qquad
\gcd(f,x^{p^{n/r}}-x)=1\quad(r\text{ prime},\ r\mid n).
\]

The witness prime and reduced polynomial are recorded in the JSON report.
Thus the irreducibility claim is exact and independently replayable without
an external factorization package.

Independently enumerating primitive reduced positive binary quadratic forms
of discriminant D gives class numbers 1, 5, 7, and 5. The code checks the
reduction boundaries, coprimality, and degree equality. It also checks that D
is fundamental, |D|<200, and no ramified prime of the quaternion algebra splits
in Q(sqrt(D)).

For each row the code reads, without executing, the exact CM input file
`twelve_under200_reproduce/cm_data/xN_cm_data.sage`. It checks the matching
discriminant, class count, every class/orientation pair, and the requested
operator. All selected quaternion generators mu have integral coordinates in
the supplied order, trace 1, norm (1-D)/4, and discriminant D. Since D is
fundamental, the quadratic order generated by mu is the full maximal order.
The operator has positive reduced norm equal to its subscript and normalizes
the supplied quaternion order in both directions. The output records the
operator's exact conjugation matrix in the order basis and the input file's
SHA256 digest. These are checks on the supplied order and CM records; this
module does not independently establish maximality of the quaternion order.

The four polynomial coefficient lists are **manuscript claims**, not a newly
computed table. Their leading coefficients do not occur in the supplied
regeneration source. That source contains the whole-table expected SHA256
fingerprint

```text
78e0bdc8e256bcb18e805156cddb89ab07f1207565b84bc90c5a312ac7b38bea
```

which cannot be used to reconstruct selected rows or check them independently
without regenerating the full table. The certificate records this fingerprint
as provenance and explicitly marks it as not recomputed.

No analytic CM divisor integration, period matching, numerical recognition,
or exact point lifting into a Hilbert class field is performed here. The
equations of the elliptic target models are resolved by Cremona label in the
supplied Sage regeneration source; this sanity check does not certify that
the listed polynomial is the x-coordinate polynomial of that analytic image.
Its result is `PASS_EXACT_SANITY`, with analytic identification explicitly
marked `NOT_RERUN`. This limitation follows the requested sanity-only scope
for the twelve-under-200 package and must remain visible in any claim of
certificate coverage.
